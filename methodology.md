
# Mapping Methodology

## 1. Purpose

The purpose of this methodology is to establish a structured approach to comparing NIST CSF 2.0 cybersecurity outcomes with CIS Controls v8.1 safeguards.
The analysis focuses on identifying how practical security measures can contribute to broader cybersecurity objectives.

## 2. Scope

The mapping covers 12 selected NIST CSF 2.0 subcategories across the following functions:
- Govern
- Identify
- Protect
- Detect
- Respond
- Recover
Two subcategories have been selected from each function to provide balanced coverage while maintaining a manageable project scope.

## 3. Mapping Process

The following analytical process is used:
1. Identify the cybersecurity objective of the NIST subcategory.
2. Identify a relevant CIS safeguard.
3. Compare the intended outcomes of both framework elements.
4. Evaluate their degree of alignment.
5. Document the rationale behind the relationship.
6. Provide a practical implementation example.
7. Identify potential audit evidence.
8. Document remaining limitations.

## 4. Alignment Criteria

### Strong Alignment
The selected CIS safeguard directly and substantially supports the cybersecurity outcome described by the NIST subcategory.

### Partial Alignment
The selected CIS safeguard supports part of the cybersecurity outcome, but additional measures, processes or controls may be necessary.

### No Direct Alignment
No directly relevant safeguard has been identified within the reviewed scope.

## 5. Audit Evidence

Potential audit evidence is included to demonstrate how an organization could support verification of security control implementation.
Examples include:
- Security policies
- Asset registers
- Access control matrices
- Vulnerability assessment reports
- Security training records
- Incident response documentation
- Backup and recovery test results
These examples are illustrative. No actual organizational evidence has been collected or evaluated.

## 6. Assumptions and Limitations

- The assessment is framework-based and organization-independent.
- Only selected framework elements are included.
- Each row examines one safeguard rather than combined safeguard coverage.
- Alignment classifications are qualitative analytical judgments.
- Additional safeguards may address identified coverage limitations.
- The assessment does not certify compliance.
- The mapping is not an official NIST or CIS crosswalk.

## 7. Validation

The official framework publications and the CIS-to-NIST crosswalk should be used to validate the selected relationships.
Any differences between this project and the official mapping should be reviewed and documented in future revisions.

## 8. Version Control

The mapping should be reviewed whenever either framework is updated.
Current framework versions:
- NIST CSF 2.0
- CIS Controls v8.1
